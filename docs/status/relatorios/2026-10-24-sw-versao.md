# Rodada 2026-10-24 · sw-versao — Atualização chegar já na primeira abertura

Branch: `claude/sw-versao` (commit a8f9851, a partir da `main` 59e8be0). Card em "Pronto para você revisar".

## O que mudou
- `vite.config.ts`: plugin que, depois do build, grava no `dist/sw.js` uma versão calculada a partir de
  todos os arquivos gerados. O jogo mudou → o `sw.js` muda → o navegador instala o service worker novo.
- `public/sw.js`: página (`index.html`) pela rede primeiro, `assets/` direto do cache, sprites e ícones do
  cache com atualização em segundo plano; apaga caches antigos ao ativar; ignora pedidos que não são GET
  ou de outro site.
- `src/updater.ts`: recarrega uma vez quando o service worker novo assume a página.
- `src/sw-versao.ts` + `tests/sw-versao.test.ts` (5 testes) e README (seção de publicação).

## Decisões
- D-20261024-10 · Versão = impressão digital do build (não é regra de negócio; não muda decisão sua).
- D-20261024-11 · Página pela rede primeiro e recarga automática (não é regra de negócio; não muda
  decisão sua). Alternativa principal: aviso "toque para atualizar" em vez de recarregar sozinho.

## Testes
- `npm ci`, `npm run build` e `npm test`: 56 testes passando.
- Ponta a ponta no Chromium (Playwright + `vite preview`): 1ª visita instala o cache `cerca-viva-<versão>`;
  depois de um "deploy" simulado (index.html e versão trocados), a 1ª abertura já mostrou a versão nova,
  recarregou uma vez, apagou o cache antigo; sem internet, o jogo abriu da cópia guardada.
- Não testado no celular (o APK só sai pelo CI da `main`).

## Atenção
Quem já tem o service worker antigo (`pvz-evolution-v1`) ainda verá esta versão só na 2ª abertura — o
antigo serve o cache primeiro. Depois disso, toda versão nova chega na 1ª abertura.

## Como testar no PC
```
git fetch origin
git switch claude/sw-versao
npm install
npm run build
npm run preview
```
Abra o endereço do preview, feche, mude algo (ex.: um texto do `index.html`), rode `npm run build` de novo
e abra de novo: a mudança aparece na hora. (No `npm run dev` o service worker não muda de versão.)

## O que precisa de você
Só o merge de `claude/sw-versao` na `main`, se aprovar. Depois do merge, vale abrir o app no celular duas
vezes e conferir que a terceira versão que você publicar já chega na primeira abertura.
